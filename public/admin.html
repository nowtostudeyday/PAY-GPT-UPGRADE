浏览器池

                
常驻 Chromium 进程与本地 Profile 缓存；任务通过 CDP 接入，每单独立 Context。页面每 2 秒自动刷新。

            


            

                

                    
日常槽位配置说明（备忘）

                

                

                    
浏览器池 = 常驻 Chromium + 本地 Profile 缓存。任务通过 CDP 接入，每单仍独立 Context（不串 Session）。每槽约 400–550 MB 内存。

                    

                        代理：池内槽位不绑定代理。每单任务启动时，从「代理池」随机抽一条启用代理，写入该单的 Context（见运行日志 proxy=yes）。
                        这样不同任务可用不同 IP，避免多账号共用一个住宅 IP。代理在左侧「代理池」管理，与浏览器池分开配置。
                    

                    

                        
                            

                                场景
                                建议槽位
                                说明
                            

                        
                        
                            

                                日常单量
                                4–8
                                稳妥，与系统配置里「前台并发」对齐即可
                            

                            

                                高峰 / 128G 独服
                                8–16
                                内存充裕时可加；注意 CPU 与其它项目占用的 ~28G
                            

                            

                                上限
                                ≤24
                                由 BROWSER_POOL_MAX_SIZE 控制，不建议无脑拉满
                            

                        
                    

                    

                        持久化：在服务器 .env 设置 BROWSER_POOL_SIZE=8、MAX_CONCURRENT_ACTIVATIONS=8 后 docker compose up -d --force-recreate app。
                        本页「应用并重载」仅改运行时，重启容器仍以 .env 为准。
